# Part II 个人反思（真实版 v2）

课程开始时我的基础是零。我不知道纵向控制里唯一能直接下发的量是加速度，不知道 jerk 是加速度的变化率，也不知道 IDM、TTC 这些词指的是什么。补课之后我才明白，速度、位置都要靠加速度积分出来，实车上这套东西又要分成决策、规划、执行几层，每层的失败方式不一样。这些是我补出来的，不是学过的。

补课的方法是追问。时空图我看了很多遍还是看不懂，最后让 AI 生成动画，一辆辆车沿着时间轴走一遍，我才读懂线的斜率和交点。读图我现在能做，公式推导做不了。这是我对自己的准确描述，也是后面所有判断的边界：我能读懂结论，不能独立推导结论。

分工从一开始就是清楚的：AI 出方案，我判断接不接受。两层架构、护栏与 fail-operational、确定性哈希、按事件而不是按采样点计数，这些设计都是它提出的，我逐条问过理由再决定。88 辆车没有进场，是复核时被指出来的；+9.5% 那个数字，我当时没有能力判断，因为我不知道正常值应该长什么样。我不把这些写成我的功劳。

但"控制"不等于接受。我做的第一件事是要求把口径说清楚：急刹次数 626 对 638 看着几乎一样，拆开是一边数事件、一边数 0.1 秒采样点，同一辆车三秒能被数三十次，数字没错，口径错了，结论就反了。第二件事是核对归属：报告里最小 TTC 0.76 秒，实际发生在旁车 665 追 664，不在 ego 身上，直接写进去会误导。第三件事是决定撤回：配对比较之后，8 个 seed 的结论方向全部反转，删掉那一段的时候，我知道留着它就是错的。

撤回比得出难。我顾虑过三件事：文章会不会显得空，推翻自己之前的判断值不值得，读起来像什么都没做。最后还是删了，判断的标准不是好看，是能不能站得住。

为了补上"我可能看不出来"这件事，我让 Codex 参与复核。它标出的问题我未必全懂，但我知道哪里需要停下来追问。补三个模型也是同一个逻辑：我不确定原结论是不是 qwen-flash 的偶然，于是让 deepseek-chat、glm-4.6、kimi-k3 用同一套提示词、同一张到达表跑 exp1 与 exp4。结果排序随场景互换：exp1 里 glm-4.6 与 qwen-flash 持平，kimi-k3 和 deepseek-chat 落后；exp4 里三个新模型都贴近 IDM，反而是 qwen-flash 最低。场景的影响大于模型的影响，原结论只能限定在一个配置下。更稳定的差异是调用代价：deepseek-chat 平均 1.05 秒/次，glm-4.6 与 kimi-k3 约 20 秒/次，glm-4.6 还有 6/45 次解析失败。同步调用下，这个差别比完成率上的几个百分点更能决定方案能不能用。

补模型这件事的跑批和整理是 AI 完成的，我的工作是三件：指定对照条件（同一提示词、同一到达表、同一 seed），判断哪些数字能写进正文，以及标注不能省的限定（kimi-k3 只能设 temperature=1，这一条不写进表注，数据就不可比）。

学到的工程判断有三条。安全不是模型不犯错，是它犯错时系统还在跑，护栏校验失败就沿用上一次的有效计划。指标要按事件算，不能按采样点算，聚合方式会把机制藏起来。结论必须带适用条件，"在这个配置下"比"LLM 不适合做规划"更接近事实。

局限我不回避：主实验只测了 qwen-flash，补充的三个模型各只有 1 个 seed、2 个场景；仿真器是单车道、不允许超车、低速区只作为扰动，参数也没有对真实道路校准；同步 API 让仿真停等，这是离实车最远的假设。

从零开始学一门课，到最后能判断哪句话不能写进报告，这是这次最大的收获。AI 把门槛降得很低，愿意钻研的人可以走得更快，但判断、取舍和署名仍然要自己承担。汽车不是我的专业，我不敢说对它有感觉，但至少现在我能读懂它的结论，也能指出它的边界。
